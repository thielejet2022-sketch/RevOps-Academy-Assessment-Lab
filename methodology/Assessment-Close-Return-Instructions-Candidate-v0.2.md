# Assessment Close & Return Instructions Candidate v0.2

**Status:** Candidate v0.2  
**Date:** 2026-08-31  
**Canonical:** No  
**Delivery method:** D4 — Dedicated Shared Assessment Project  
**Pilot:** HP-001  
**Scope:** A1 Dynamic GTM Diagnostic only

## Critical Boundary
This Candidate does not launch HP-001. It defines the evidence-close and operator handoff for the D4 Shared Project architecture validated in DR-001.

---

# 1. Trigger

Use only after the A1 decision gate and executive readout are complete and the facilitator has said:

> **ASSESSMENT EVIDENCE CLOSED**

From this point:
- assessment evidence is closed;
- participant should not revise prior answers for evaluation purposes;
- no scoring, coaching, proficiency, or Role Fit judgment is provided inside the assessment conversation before separate evaluation;
- post-assessment experience feedback may continue but is not scored evidence.

---

# 2. Participant-Facing Close Message

## Assessment complete

**ASSESSMENT EVIDENCE CLOSED**

Thank you. You've completed the RevOps Assessment Pilot interaction.

Please leave your earlier responses as they are. Your original reasoning path, including questions, uncertainty, changes of mind, and decisions, is part of the evidence the pilot is designed to observe.

You have **not** received a score or developmental evaluation yet. Review happens separately.

Because this assessment took place inside a dedicated Shared ChatGPT Project, you do not need to create or publish a public share link unless JET specifically asks you to use another verified return method.

Please tell JET that you have completed the pilot using the same communication channel used for the invitation.

Suggested message:

> **RevOps Pilot complete — assessment evidence closed.**

JET will confirm receipt and review the assessment conversation separately.

---

# 3. D4 Evidence Handoff

The dedicated Shared Project itself is the immediate operational source for the closed participant conversation because JET, as Project owner, can access participant chats in that Project.

Operator procedure:
1. Confirm participant says the pilot is complete.
2. Confirm the participant chat contains the interaction from READY through **ASSESSMENT EVIDENCE CLOSED**.
3. Assign/confirm participant ID `HP-001`.
4. Do not alter participant messages or ask the participant to reconstruct missing reasoning.
5. Preserve participant identity separately from any public methodology artifact.
6. Do not commit raw transcript, identifiable excerpts, contact information, or participant-specific results to the public RevOps Academy GitHub repository.
7. Create a separate evaluator evidence record from the closed conversation.
8. Begin evaluation only after evidence is considered closed.

If the participant chat is incomplete or unavailable, record that limitation and use only a separately verified private fallback. Do not improvise by making the participant publish the conversation publicly.

---

# 4. Private Evidence Retention Boundary

For HP-001, the Shared Project may serve as the immediate private operational record while evaluation is performed.

Before any broader pilot expands beyond HP-001, decide whether participant transcripts require an additional private system of record outside ChatGPT.

Public GitHub remains prohibited for identifiable participant evidence.

This Candidate does not promise a specific deletion or retention period that has not been operationally verified.

---

# 5. Participant Experience Feedback

After evidence closure, the facilitator or JET may ask for experience feedback. It must remain clearly separate from scored evidence.

Suggested questions:
- What felt realistic?
- What felt confusing or artificial?
- Did the facilitator seem to lead you toward an answer?
- Did you feel able to ask for the information you needed?
- Was there an important RevOps capability you could not demonstrate?
- Did any ChatGPT behavior feel surprising or distracting?
- Roughly how long did the experience take?

If the participant encountered a generated-image issue or other platform oddity, record it as **pilot experience/methodology evidence**, not participant performance evidence.

---

# 6. Evidence Integrity Rules

Do not:
- edit participant answers for clarity;
- remove weak or contradictory reasoning because a later answer is stronger;
- add evaluator interpretation into the participant transcript;
- infer missing participant questions/answers;
- convert post-assessment feedback into scored competency evidence;
- treat facilitator-generated text as participant evidence;
- use unrelated personal information from the participant's account.

The evaluator record should distinguish participant statements/actions from facilitator statements and record material facilitator contamination separately.

---

# 7. Known Prototype Risk

DR-001 established that explicit requests to generate/draw a graphic can invoke image generation despite Project Instructions prohibiting it, and generated images may access/synthesize unrevealed hidden evidence resident in the runtime.

JET accepted this risk for the current prototype and directed that additional prompt-only optimization cycles not be spent on it.

For HP-001:
- participant is instructed that generated graphics/images are outside the supported interaction;
- if participant nevertheless requests one and leakage occurs, preserve the event;
- do not treat the leaked content as participant-discovered evidence for scoring without evaluator qualification;
- classify the incident as facilitator/platform contamination;
- stop only if the contamination is material enough that useful evaluation is no longer defensible.

The longer-term interactive website/application should control evidence access programmatically rather than relying on Project Instructions alone.

---

# 8. Post-HP-001 Review

Before expanding to HP-002 or adding A4, review:
- participant navigation/usability;
- participant feedback;
- facilitator leading/contamination incidents;
- evidence gaps;
- time burden;
- whether the A1-only pilot produced useful developmental evidence;
- evaluator confidence and disagreement;
- privacy/evidence-retention handling;
- whether the generated-image residual risk affected assessment usefulness.

Then decide whether to repeat A1, add A4, revise delivery, or move toward the interactive application architecture.
